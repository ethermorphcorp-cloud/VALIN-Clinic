## Feature

### ระบบผู้ใช้และสิทธิ์
- Login ด้วย username/password (hash + salt) และ session token เก็บใน CacheService อายุ 6 ชม.
- มี 2 ระดับคือ **admin** และ **staff** โดย Dashboard, รายงาน, ค่าใช้จ่าย & จัดซื้อ และตั้งค่าคลินิก ใช้ได้เฉพาะ admin
- ผู้ใช้เปลี่ยนรหัสผ่านเองได้ และ admin รีเซ็ตรหัสพนักงานได้
- บันทึกทุกการเปลี่ยนแปลงลง AuditLog

### Flow การทำงาน
สร้างประวัติคนไข้ → จัดยา-เบิกยา (สถานะ **จัดยาแล้ว** — มักจัดล่วงหน้าก่อนวันนัด) → ลูกค้ามา Front กด **รอพบแพทย์** (ได้เลขคิวของวัน) → Front เรียกเข้าพบ โดยเลือกแพทย์ → **พบแพทย์** → แพทย์เพิ่มบันทึกการรักษา (บันทึกแล้วเป็น **รอชำระเงิน** ทันที) → Front รับชำระเงิน (**เสร็จสิ้น**)

เลขคิวเริ่มนับเมื่อเปลี่ยนเป็นรอพบแพทย์ รันต่อเนื่องในแต่ละวัน (เริ่ม 1 ใหม่ทุกวัน) และคนไข้ใช้เลขเดิมตลอดจนเสร็จสิ้น; ย้อนสถานะได้ตราบที่ยังไม่ชำระ; เสร็จสิ้น = ชำระเงินแล้ว; **ยังไม่มีบันทึกการรักษาในขั้นจัดยาแล้ว/รอพบแพทย์** — ฟอร์มบันทึกการรักษาเปิดได้ตั้งแต่ขั้นพบแพทย์; บันทึกการรักษาที่สร้างเองโดยไม่ผ่านการจัดยาเริ่มที่พบแพทย์; ตอนกด รอพบแพทย์ วันที่ของบันทึกที่จัดยาไว้ล่วงหน้าจะเปลี่ยนเป็นวันที่ลูกค้ามา

### เมนูหลัก
1. **Dashboard** (admin): **รายได้** = ที่เก็บจากลูกค้า (หัตถการ, โปร, Canula, อื่นๆ — เฉพาะบันทึกที่ชำระแล้ว) + ที่เก็บจากเซลล์ (รายงานรายเซลล์ ณ ราคาทุน); **รายจ่าย** = ค่าใช้จ่าย + จัดซื้อ + ส่วนแบ่งแพทย์ + ส่วนแบ่งเซลล์; กำไร = รายได้ − รายจ่าย. การ์ด: รายได้รวม, รายจ่ายรวม, กำไร (พร้อม %กำไร), จำนวนคนไข้; กราฟ: รายเดือน (แสดงเฉพาะเดือนที่มีข้อมูล) → รายได้รายหมวดหมู่ (รวมกันเท่ากับรายได้รวม) + รายจ่ายรายหมวดหมู่ (รวมกันเท่ากับรายจ่ายรวม) → สัดส่วนส่วนแบ่งแพทย์ / ส่วนแบ่งเซลล์ / รายได้รายโปรโมชัน เลือกช่วงวันที่ได้ และ cache ผลไว้ (ล้างอัตโนมัติด้วย version bump ทุกครั้งที่มีการบันทึก)
2. **ข้อมูลคนไข้**: ประวัติ (เลข HN ที่กรอกเอง ห้ามซ้ำ, ชื่อ, ชื่อเล่น, เบอร์, วันเกิด, เพศ, อีเมล, รูป) และรหัสระบบที่รันอัตโนมัติ (ใช้ภายใน ไม่แสดงในฟอร์ม), ค้นหาด้วยชื่อ/เบอร์/HN, หน้าโปรไฟล์ที่รวมประวัติการรักษาและยาฝาก
3. **ระหว่างดำเนินการ** (ต่อจากจัดยา-เบิกยา; Front ใช้เป็นหลัก): กระดาน kanban ของวัน 5 คอลัมน์ จัดยาแล้ว / รอพบแพทย์ / พบแพทย์ (แยกกลุ่มตามชื่อแพทย์) / รอชำระเงิน / เสร็จสิ้น พร้อมการ์ดจำนวนคนไข้ในแต่ละสถานะ เรียงตามเลขคิว เลือกวันที่ดูย้อนหลังได้ มีปุ่มรีเฟรช และรีเฟรชเองทุก 10 นาที (เป็นหน้าเดียวที่รีเฟรชเอง); ปุ่มที่ Front ใช้: จัดยาแล้ว → รอพบแพทย์, รอพบแพทย์ → พบแพทย์ (เลือกแพทย์ก่อน), รอชำระเงิน → ชำระเงิน (เสร็จสิ้น) และย้อนสถานะ; การ์ดจัดยาแล้วและรอชำระเงินไม่แสดงวันที่ค้าง; คอลัมน์จัดยาแล้วมีช่องค้นหาชื่อ/เบอร์/HN และถ้าชื่อคนไข้ยังเป็น **(รออัพเดท)** การ์ดมีปุ่ม "แก้ไขประวัติคนไข้"; การ์ดพบแพทย์มีปุ่ม "สร้างบันทึกการรักษา"; ปุ่มย้อนสถานะเป็นไอคอนข้างปุ่มหลัก; แพทย์/เซลล์แยกบรรทัด; **แจ้งเตือน**: เมื่อมีคนไข้เปลี่ยนจากพบแพทย์เป็นรอชำระเงิน เมนู "ระหว่างดำเนินการ" ขึ้นตัวเลขสีแดงและมีข้อความแจ้ง (ตรวจตอนเข้าสู่ระบบและทุกครั้งที่เปลี่ยนหน้า ไม่มีตัวตั้งเวลา) เปิดกระดานแล้วตัวเลขหาย; กดการ์ดเพื่อดูรายละเอียด
4. **จัดยา-เบิกยา**: เบิกยาจากสต๊อกให้คนไข้ (ไม่ทราบชื่อ/ไม่มีในรายชื่อ — พิมพ์ชื่อแล้วบันทึกได้เลย ระบบสร้างประวัติคนไข้ชื่อ "ชื่อที่พิมพ์ (รออัพเดท)" ให้ แล้วแก้ไขข้อมูลทีหลังได้ ชื่อ/เบอร์ในบันทึกที่เกี่ยวข้องเปลี่ยนตาม; เลือกเซลล์, ตัดสต๊อกทันที, เก็บราคาทุน — ไม่มีราคาขาย เพราะลูกค้าจ่ายค่ายาให้เซลล์โดยตรง) เมื่อบันทึกการเบิก ระบบสร้างบันทึกการรักษา (สถานะ **จัดยาแล้ว**) ให้ทันที; รายการที่บันทึกพร้อมกันแสดงเป็นกลุ่มเดียว (HN, ชื่อคนไข้, เซลล์, สถานะ รวมแถว แยกแถวเฉพาะยา/จำนวน/ราคา) ค้นหาด้วยชื่อ/เบอร์/HN กรองตามชื่อเซลล์ กรองตามสถานะการรักษา (เริ่มต้น = จัดยาแล้ว; เลือกเสร็จสิ้น/ทั้งหมดได้) แนบรูปยาที่เบิกได้สูงสุด 8 รูปต่อการเบิก (ตอนสร้างรายการ หรือภายหลังจากเมนู "จัดการ" > รูปยาที่เบิก — เพิ่ม/ลบได้ทั้ง admin และ staff; ย่อรูปก่อนอัปโหลด เก็บใน Drive โฟลเดอร์ปี/เดือน/วันเดียวกับรูป OPD) และมีเมนู "จัดการ" (ไปที่บันทึกการรักษา, รูปยาที่เบิก, ลบรายการยา — admin)
5. **บันทึกการรักษา**:
   - เลือกคนไข้ และเซลล์ เปิดบันทึกที่ "จัดยาแล้ว" มาเพิ่มหัตถการ/รายการอื่นๆ (หรือเพิ่มบันทึกใหม่เองก็ได้) สถานะการรักษา: จัดยาแล้ว → รอพบแพทย์ → พบแพทย์ → รอชำระเงิน → เสร็จสิ้น (หน้านี้แสดงตั้งแต่รอพบแพทย์เป็นต้นไป ตัวกรองมี 4 สถานะ — staff เริ่มที่ "พบแพทย์", admin เริ่มที่ "ทั้งหมด"; กดแถวเพื่อดูประวัติคนไข้ (มีปุ่ม "เพิ่มบันทึกการรักษา" เมื่ออยู่ขั้นพบแพทย์); เมนู "จัดการ" เปลี่ยนตามสถานะ: รอพบแพทย์ = ดูประวัติการรักษา · พบแพทย์ = สร้างบันทึกการรักษา, ย้อนไปรอพบแพทย์ · รอชำระเงิน = พิมพ์ใบเสร็จ, แก้ไข, ลบ · เสร็จสิ้น = พิมพ์ใบเสร็จ, ลบ (ลบเฉพาะ admin และมีให้ยืนยัน); กด "บันทึกการรักษา" แล้วสถานะเป็นรอชำระเงินทันที และแถวบันทึกใหม่ของหัตถการ/โปรเลือกแพทย์ที่เข้าพบให้อัตโนมัติ)
   - 1 เวชภัณฑ์ (ตัดสต๊อก) · 2 หัตถการ (เลือกแพทย์และหัตถการต่อบรรทัด — คนไข้ 1 คนทำกับแพทย์หลายคนได้, ยอดรวม = จำนวนเงินหัตถการ) · 3 ยา: รายการยาจากใบเบิก (ดึงอัตโนมัติ, ระบุจำนวนที่ใช้/ฝาก และวันหมดอายุ, ไม่คิดเงินในยอดรับชำระ) และรายการซื้อยาเพิ่มหน้าคลีนิค 2 กลุ่ม — (ไม่คิดค่ายา) ตัดสต๊อก ไม่คิดเงิน และ (คิดค่ายา) ตัดสต๊อกเช่นกัน มีคอลัมน์ราคาต่อหน่วย (ดึงจากราคาขายในสต๊อกตามจำนวน แก้เองได้) และจำนวนเงินรวม = จำนวนที่เบิก × ราคาต่อหน่วย รวมอยู่ในยอดรับชำระ; ต้นทุนของทั้งสองกลุ่มไปอยู่ในรายงานรายเซลล์พร้อมหมายเหตุ; **รายการจ่ายยาทาน** (ค้นหาจากรายการยาทาน — จำนวน, ราคา/หน่วย ดึงจากราคาขาย แก้เองได้, จำนวนเงิน = จำนวน × ราคา; ตัดสต๊อก และรวมในยอดรับชำระ), ใช้ยาฝาก, ถือยาเข้า, Messenger · 4 รายการอื่นๆ (โปรหน้าคลีนิค เลือกแพทย์ต่อบรรทัด, Canula หลายรายการ — ระบุรายการ จำนวนที่ใช้ จำนวนเงิน, อื่นๆ); แต่ละหัตถการมีช่องรายละเอียด (พิมพ์ใต้รายการที่เลือก) และ "รายละเอียดการรักษา" อยู่ใต้รูปถ่าย OPD

   - **ชำระเงิน** เป็นขั้นตอนสุดท้าย (ปุ่ม "บันทึกและชำระเงิน" หรือปุ่มชำระเงินในรายการ): สรุปยอด, วิธีชำระเงิน, สถานะ และพิมพ์ใบเสร็จ

7. **รายงาน** (admin) แยกเป็น 2 เมนู: **รายงานรายวัน** และ **คิดค่ายาเซลล์** (รายงานรายเซลล์) — เลือกช่วงวันที่และชื่อเซลล์ ดาวน์โหลด PDF ได้
   - รายงานรายวัน: วันที่, ชื่อคนไข้, ชื่อเซลล์, รายละเอียดตามใบเสร็จ, จำนวนเงิน
   - รายงานรายเซลล์: รายได้ที่คลินิกเก็บจากเซลล์ ณ ราคาทุน (ไม่มีราคาขาย) แสดงแบบ pivot — วันที่ > ชื่อเซลล์ > ชื่อคนไข้ > รายการยา (จำนวน, ราคาทุน/หน่วย, **จำนวนเงิน (เรียกเก็บจากเซลล์)** สีเขียว, **จำนวนเงิน (ส่วนต่างคืนเซลล์)** สีแดง = ยอดที่เก็บจากลูกค้า − ราคาทุน เฉพาะรายการซื้อยาเพิ่มหน้าคลีนิค (คิดค่ายา), หมายเหตุ) พร้อมยอดรวมต่อเซลล์/วัน และสรุปยอดแต่ละเซลล์ (PDF สรุปท้ายรายงาน: ยอดเรียกเก็บจากเซลล์ / ยอดส่วนต่างคืนเซลล์ / ยอดสุทธิ); คลิกแถวเพื่อดูตัวอย่างและดาวน์โหลด PDF ของเซลล์/วันนั้น
8. **จัดการสินค้า/บริการ (สต๊อก)**: รายการเวชภัณฑ์ **รายการยาสต๊อกคลีนิค** (ราคาทุน/ราคาขายเห็นเฉพาะ admin, ไม่มีคอลัมน์จำนวนฝาก, อัพเดตสต๊อกยากรอกเฉพาะจำนวนรับเข้า, คลิกแถวเพื่อดูประวัติการเคลื่อนไหว; ปุ่ม Template CSV / อัปโหลด CSV ซ่อนไว้) และ **รายการยาทาน** (ตาราง: รายการยา, หมวดหมู่, จำนวนขั้นต่ำ, จำนวน stock, หน่วย, ราคาขาย, จัดการ — มีราคาขายราคาเดียว) (สต๊อก, อัพเดตสต๊อก, ประวัติการเคลื่อนไหว, นำเข้า CSV) และ **รายการค่าหัตถการ** (ชื่อ, หมวดหมู่, ราคา, เปิด/ปิดใช้งาน — admin แก้ไข) · ข้อความ LINE ที่เกี่ยวกับสต๊อกใช้คำว่า "สต๊อกคลีนิค" (เช่น เพิ่มสต๊อกคลีนิค) · เปลี่ยนสถานะโปรโมชันได้เฉพาะ admin
9. **ค่าใช้จ่าย & จัดซื้อ** (admin): บันทึกค่าใช้จ่ายแยกหมวด และใบสั่งซื้อ (PO) ที่มีหลายรายการ โดยเลือกประเภทใบสั่งซื้อ: **ยา(จากเซลล์)** ช่องผู้จำหน่ายเป็นชื่อเซลล์ (เลือกจากรายชื่อ) หรือ **อื่นๆ** พิมพ์ชื่อผู้จำหน่ายเอง — คลิกแถวใน "จัดซื้อ" เพื่อดูรายละเอียด (สรุป + รายการสินค้า) ที่แผงด้านขวา แล้วกดแก้ไขต่อได้
   - **flow จัดซื้อ**: admin สร้างใบสั่งซื้อ (สถานะ **รอตรวจรับ** — ยังไม่เพิ่มสต๊อก แก้ไขได้) → staff เปิดเมนู **เช็ครายการจัดซื้อ** (มีตัวเลขจำนวนที่รออยู่บนเมนู, ไม่แสดงราคา) กดตรวจรับ กรอกวันที่รับของและ **จำนวนที่รับจริง** ของแต่ละรายการ (ขึ้น ครบ / ขาด / เกิน) แล้วยืนยัน → เพิ่มเข้าสต๊อกคลีนิคตามจำนวนที่รับจริง และส่ง LINE "เพิ่มสต๊อกคลีนิค" ให้ admin (บอกว่ารับครบ/ไม่ครบ) · ใบที่ตรวจรับแล้วแก้ไขไม่ได้ (ลบแล้วสร้างใหม่ — การลบจะหักจำนวนที่รับออกจากสต๊อก) · ยอดรวมใบสั่งซื้อคิดตามจำนวนที่รับจริง และ Dashboard นับเป็นรายจ่ายเฉพาะใบที่ตรวจรับแล้ว
   - **สำรองข้อมูล** (ตั้งค่าคลินิก > สำรองข้อมูล, admin): เลือกวันที่ตัดยอด ตรวจสอบข้อมูลที่จบแล้ว (บันทึกการรักษาที่ชำระ/ยกเลิก + ใบจัดยา, ค่าใช้จ่าย, ใบสั่งซื้อ, ประวัติสต๊อก, Audit) แล้วกด Backup (ยืนยันด้วย username + password) — สร้างไฟล์ Sheets ใหม่ในโฟลเดอร์ "back up data" ชื่อ "ข้อมูลตั้งแต่ … - …" ตรวจว่าคัดลอกครบก่อนลบออกจากชีตหลัก; เก็บสรุปรายวันไว้ในแท็บ DailySummary ทำให้ Dashboard ยังรวมยอดช่วงที่ย้ายไป; แท็บ Backups ในชีตเก็บรายการไฟล์ (dropdown ในหน้านี้แสดงชื่อไฟล์ + Sheet ID); รายงานรายวัน/รายเซลล์และประวัติการรักษาในระบบแสดงเฉพาะข้อมูลที่ยังอยู่
  - **นำเข้าข้อมูล** (ตั้งค่าคลินิก > นำเข้าข้อมูล, admin · การ์ด "ลบข้อมูลตัวอย่าง" และ "ลบข้อมูลที่สร้างก่อนวันนี้" ซ่อนไว้แล้ว เปิดคืนได้ด้วย SHOW_DELETE_TOOLS ใน gas/index.html): ดาวน์โหลด Template CSV แล้วนำเข้าข้อมูลเดิม 3 ชุดตามลำดับ — 1 **ข้อมูลคนไข้** → 2 **บันทึกการรักษา** (แถวที่เลขอ้างอิงเดียวกันคือครั้งเดียวกัน แต่ละแถวมีแพทย์/หัตถการของตัวเอง ชำระแล้ว คำนวณส่วนแบ่งให้) → 3 **ประวัติจัดยา-เบิกยา** (เข้าไปอยู่ในการรักษาของคนไข้คนเดียวกันวันเดียวกัน ไม่มี = สร้างการรักษาของตัวเอง; มีผลกับรายงานคิดค่ายาเซลล์) · ระบบ**ตรวจทั้งไฟล์ก่อน** ถ้ามีแถวผิดจะบอกเลขแถวและเหตุผลและไม่นำเข้าเลย (ไฟล์ละไม่เกิน 5,000 แถว; วันที่เป็น ค.ศ. หรือ พ.ศ. ก็ได้) · ข้อมูลที่นำเข้าไม่ตัดสต๊อก · **ลบข้อมูลตัวอย่าง** ล้างข้อมูลทั้งระบบ (เก็บบัญชีผู้ใช้และข้อมูลบริษัท) ต้องยืนยันด้วยชื่อผู้ใช้/รหัสผ่าน และใช้ไม่ได้ถ้าเคย Backup ข้อมูลจริงแล้ว
  - **ลบข้อมูลที่สร้างก่อนวันนี้** (แท็บเดียวกัน, admin): ลบเฉพาะ "รายการ" ที่สร้างก่อนวันนี้ (คนไข้ บันทึกการรักษา จัดยา-เบิกยา ยาฝาก ประวัติสต๊อก ค่าใช้จ่าย ใบสั่งซื้อ Audit) โดยดูจากวันที่สร้าง (CreatedAt) · เก็บแพทย์ เซลล์ โปรโมชัน หมวดหมู่ หัตถการ สินค้าสต๊อก บัญชีผู้ใช้ ข้อมูลบริษัท และรายการที่สร้างตั้งแต่วันนี้ · รายการจัดยา/ยาฝากตามการรักษาของมัน · คนไข้ที่ยังมีรายการเหลืออ้างอิงอยู่ไม่ถูกลบ · เก็บรายการสต๊อกล่าสุดของแต่ละสินค้าไว้เป็นยอดคงเหลือ · มีตารางจำนวนแถวก่อนลบ ต้องยืนยันด้วยชื่อผู้ใช้+รหัสผ่าน และใช้ไม่ได้ถ้าเคย Backup แล้ว
10. **จัดการโปรโมชันหน้าคลินิก**: ชื่อโปร, ราคา, %ส่วนแบ่งแพทย์ (ส่วนคลินิกคำนวณเป็น 100 − %แพทย์) และเปิด/ปิดใช้งาน
11. **ตั้งค่าคลินิก** (admin): แพทย์/เซลล์ (%คอมมิชชัน, ยอดขั้นต่ำ), หมวดหมู่ (สินค้า/หัตถการ/ค่าใช้จ่าย), ข้อมูลบริษัท (ชื่อ, ที่อยู่, เบอร์, เลขผู้เสียภาษี, โลโก้, รูปหน้า login) และพนักงาน (สิทธิ์, LINE ID)

### LINE Messaging API
- ปุ่ม **ส่งข้อมูลไป LINE** ส่งสรุปยอดรายวัน ตามด้วยรายการ **สต๊อกใกล้หมด** (คงเหลือต่ำกว่าจำนวนขั้นต่ำ หรือหมด แยก ยา / ยาทาน / เวชภัณฑ์ มีปุ่มดูสต๊อกทั้งหมด) ให้ admin ทุกคนที่กรอก LINE ID ไว้
- **แจ้งปรับจำนวนสต๊อก** อัตโนมัติถึง admin เดียวกัน เมื่อบันทึกจัดซื้อที่ผูกสต๊อก, อัพเดตสต๊อก หรือปรับสต๊อก (รายการ, จำนวนที่เปลี่ยน, คงเหลือ) — ถ้าส่ง LINE ไม่ได้ การบันทึกยังสำเร็จตามปกติ
- **หน้าสต๊อกมือถือ** (`gas/StockView.html`, `?page=stock&t=…`): ดูสต๊อกทั้งหมดแบบอ่านอย่างเดียว ค้นหา/กรองตามประเภท/เฉพาะใกล้หมด ไม่ต้อง login — ลิงก์ในข้อความ LINE ใช้ได้ 24 ชั่วโมง (ลงลายเซ็นด้วย Script Property `STOCK_LINK_SECRET` ที่ระบบสร้างให้เอง; ตั้ง `APP_URL` เป็น /exec URL ของแอปเพื่อให้ลิงก์ชี้ที่ deployment นั้น) ไม่แสดงราคาทุน
- ตั้ง trigger ส่งสรุปยอดอัตโนมัติทุกวันตามเวลาที่กำหนดได้
- Chatbot ผ่าน webhook (`doPost`) รองรับคำสั่งเหล่านี้ โดยตรวจสิทธิ์จาก LINE ID ของพนักงานที่ Active
  - `Line ID ของฉัน` ตอบกลับ LINE user id ของผู้ส่ง
  - `สรุปยอดวันนี้`
  - `สรุปยอดวันอื่น [yyyy-MM]` แสดงปฏิทินให้กดเลือกวัน
  - `สรุปยอดวันที่ yyyy-MM-dd`
  - `เช็ค stock ใกล้หมด` รายการสต๊อกที่ต่ำกว่าขั้นต่ำ
  - `เช็คสต๊อก` / `สต๊อกทั้งหมด` การ์ดสรุปสต๊อก ให้เลือก "ดูรายการใกล้หมด" หรือ "ดูสต๊อกทั้งหมด" (เปิดหน้าสต๊อกมือถือ ลิงก์ 24 ชม.)
- Rich menu (`line-richmenu/richmenu.jpg`, 2500×1686, template A + B C D): A โลโก้ = `สรุปยอดวันนี้` · B `สรุปยอดวันอื่น` · C `เช็คสต๊อก` · D `Line ID ของฉัน` (ต้นแบบ `richmenu.html`)
  - `สต๊อก <ชื่อ>` ค้นหารายการ (สูงสุด 30 รายการ + ปุ่มดูต่อในหน้าเว็บ)

### อื่นๆ
- อัปโหลดไฟล์ใหญ่แบบ resumable chunk ผ่าน server โดยไม่ส่ง OAuth token ไปที่ client
- Cache master data และรายการ autocomplete ของคนไข้/สต๊อกเพื่อลดการอ่าน Sheet (เก็บใน CacheService แบ่งเป็นหลายก้อน ก้อนละไม่เกิน ~80KB จึงใช้ได้แม้มีคนไข้หลายพันราย ล้างทั้งชุดเมื่อมีการบันทึก)
- หน้า **ข้อมูลคนไข้** ค้นหาและแบ่งหน้าในเบราว์เซอร์จากรายชื่อที่โหลดไว้แล้ว (ไม่ต้องรอเซิร์ฟเวอร์ทุกครั้งที่ค้นหา/เปลี่ยนหน้า) และดึงรายชื่อใหม่เบื้องหลังทุกครั้งที่เข้าหน้า
- หน้ารายการ (สต๊อก, บันทึกการรักษา, จัดยา-เบิกยา, ค่าใช้จ่าย, จัดซื้อ) จำผลลัพธ์ล่าสุดของแต่ละหน้า/ตัวกรอง **ไว้ในหน่วยความจำเท่านั้น** (ไม่ใช้ localStorage เพราะมีข้อมูลคนไข้): เปิดซ้ำแสดงทันทีแล้วรีเฟรชเบื้องหลัง และล้างทิ้งเมื่อมีการบันทึกหรือออกจากระบบ
- การโหลดแสดงเป็น skeleton/shimmer ตามรูปทรงของหน้า, เส้นความคืบหน้าบางๆ ด้านบนขณะอ่านข้อมูล (ไม่บล็อกหน้าจอ) และหน้าจอ "กำลังบันทึก..." เมื่อบันทึก/สำรอง/อัปโหลด
- `seedDemoData` สำหรับใส่ข้อมูลตัวอย่างตาม flow ปัจจุบัน: ประวัติก่อนวันนี้จบครบ (ชำระแล้ว หรือยกเลิก) ส่วนของวันนี้กระจายทุกขั้น — จัดยาแล้ว 2 (จัดล่วงหน้าเมื่อวาน), รอพบแพทย์ 2, พบแพทย์ 2 (คนละแพทย์), รอชำระเงิน 2, เสร็จสิ้น 2 (รวมตัวอย่างครบวงจร HN1011 และตัวอย่างยาครบทุกแบบ HN1012 — บันทึกการรักษาวันนี้มียาคิดเงินทุกแบบ (ซื้อยาเพิ่ม คิดค่ายา, จ่ายยาทาน) และยาไม่คิดเงินทุกแบบ (ใบเบิก, ซื้อยาเพิ่ม ไม่คิดค่ายา, ใช้ยาฝากจากครั้งก่อน, ถือยาเข้า, Messenger)) พร้อมเลขคิวของวันและแพทย์ที่เข้าพบ; ก่อนขั้นพบแพทย์ยังไม่มีบันทึกการรักษา

## ฐานข้อมูล (Google Sheets)

Patients, Records, Stock, StockLog, MedWithdrawals, MedDeposits, Procedures, Expenses, Orders, OrderLines, Doctors, Sales, Promotions, Categories, Staff, ClinicSettings, Counters, AuditLog โดยโครงสร้างคอลัมน์ที่ใช้งานจริงอยู่ที่ `CONFIG.HEADERS` ใน `Code.js` (คอลัมน์ใหม่เพิ่มต่อท้ายเสมอ — ชีตเดิมอัปเดตหัวตารางเองเมื่อเปิดใช้งาน หรือรัน `setupProject` ซ้ำได้)

## การติดตั้ง

1. รัน `setupProject` จาก Apps Script editor เพื่อสร้าง Spreadsheet, ทุก sheet, โฟลเดอร์ใน Drive และบัญชี admin เริ่มต้น
2. (ไม่บังคับ) รัน `seedDemoData` เพื่อใส่ข้อมูลตัวอย่าง
3. Deploy เป็น Web app
4. ตั้ง Script Property `LINE_CHANNEL_ACCESS_TOKEN`
5. (ไม่บังคับ) สร้าง deployment แยกอีกตัวสำหรับ LINE Webhook URL โดยทุกครั้งที่อัปเดตโค้ดต้องเลือกเวอร์ชันใหม่ให้ทั้งสอง deployment

> ⚠️ บัญชี admin เริ่มต้นคือ `admin` / `12345` ควรเปลี่ยนรหัสทันทีหลังติดตั้ง
